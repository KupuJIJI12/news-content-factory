# NewsContentFactory («Контент завод»)

## Суть
Конвейер, который собирает новости города (MVP: Отрадный, Самарская область) из открытых источников, склеивает повторы в один сюжет, переписывает через LLM, проверяет факты и после одобрения модератора публикует в канал Max. Назначение: выпускать 3–4 интересных поста в день, а модератор тратит на пост меньше минуты, в том числе с телефона.

## Стек и архитектура
- **Бэкенд:** C#, .NET 10, модульный монолит на ASP.NET Core (minimal API), PostgreSQL (EF Core, Npgsql), Hangfire (сбор, конвейер, отложенная публикация), SignalR (живые счётчики).
- **Админка:** `admin/`, React + TypeScript + Vite + Mantine 8, адаптивная, всегда светлая тема, интерфейс на русском.
- **LLM:** GigaChat — основной провайдер (работает из РФ); YandexGPT и OpenAI-совместимые подключаются записью в БД. Зарубежные провайдеры не используются.
- **Конвейер:** Collection (RSS, HTML, VK) → Processing (фильтр города, склейка, оценка интереса 1–10, рерайт, проверка фактов) → модерация в админке → Publishing (Max).
- **Модули** (`src/`): `Api`, `Domain`, `Infrastructure`, `Collection`, `Processing`, `Llm`, `Publishing`. Модули общаются через публичные интерфейсы: Processing не знает о конкретных сборщиках и площадках, Publishing не знает о LLM. Тесты лежат в `tests/` по модулям.
- **Документы:** спецификация `docs/superpowers/specs/2026-10-23-news-content-factory-design.md`, планы в `docs/superpowers/plans/`, статус в `docs/PROGRESS.md`.

## Статус
- План 1 (конвейер) и план 2 (админ-API и веб-админка) выполнены и влиты в `main`. Проверка Max вживую и автонастройка источников пройдены.
- Работает локально на Windows: бэкенд через `dotnet`, админка через `npm`, PostgreSQL на машине владельца. Развёртывание на VPS (Docker, nginx) не планируется.
- Отложено: поведение после сна ПК, мелкие исправления (409 вместо 500 при гонках и др.), `NewsFactory.EvalBench`. Полный список в `docs/PROGRESS.md`.

## Правила проекта
- Секреты только в переменных окружения (`MAX_BOT_TOKEN`, ключи LLM, `ADMIN_LOGIN`, `ADMIN_PASSWORD`). В БД хранятся только имена переменных.
- Удаление только пометкой: сюжет получает статус `Deleted` (только из «Отклонено»), источник получает `DeletedAt`. Иначе удалённое собралось бы заново.
- В постах нет фактов, которых нет в источниках; источники в тексте не указываются. Название города не пишется в заголовке.
- Фото из источников публикуются только по решению модератора и с учётом авторских прав. По умолчанию пост уходит без фото.
- Работа по TDD: сначала падающий тест. Тесты: `dotnet test` (для тестов с базой задайте `NEWSFACTORY_TEST_PG`), админка: `npm --prefix admin test`.
- Ветки и PR: основная ветка `main`, правки идут через PR, который владелец мержит сам.
